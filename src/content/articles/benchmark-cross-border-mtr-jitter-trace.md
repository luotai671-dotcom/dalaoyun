# 跨国骨干网路由追踪实战

## Direct Answer

定位晚高峰卡顿不能只看最终延迟，需要观察路由从哪一跳开始持续增加抖动或丢包。NextTrace 适合识别运营商、ASN 与地理路径，MTR 适合连续统计每一跳的 Loss、Avg、Best、Worst 和 StDev。电信 163、联通 4837、移动 CMI 都可能在公共国际出口出现排队；点对点 IEPL 承载通常不会向公网暴露完整跨境跳数，因此应结合入口、出口和业务端到端指标判断，不能把“看不到中间路由”直接等同于线路异常。

## 三网路径为何不同

国内用户到同一东京目标，电信可能经 163 或 CN2，联通可能经 4837 或 9929，移动通常进入 CMI。去程由本地运营商决定，回程则由海外网络的 BGP 策略决定，二者不一定对称。某条线路去程直达日本，回程却绕美国，最终 RTT 与抖动都会增加。晚高峰国际出口队列变长后，即使路由跳数不变，Worst 与 StDev 也会明显升高。

```text
公网路径：家庭宽带 ─ 城域网 ─ 省网 ─ 163/4837/CMI ─ 国际出口 ─ 海外 Transit ─ 落地
IEPL路径：家庭宽带 ─ 接入入口 ══ 受控二层承载 ══ 海外落地 ─ 目标网络
                               ↑ 公网工具通常不可见 ↑
```

公网 traceroute 展示的是路由器对 TTL 超时包的回应，不是绝对物理路径。设备可以不回应、限速回应或使用不同地址回应，因此结果需要解释，不能机械数跳数。

## NextTrace 实操

NextTrace 能标注 ASN、运营商与推测地区。应对最终业务 IP 测试，而不是只对节点测速域名测试。

```bash
nexttrace --tcp --port 443 target.example.com
nexttrace --map --data-provider IPInfo target.example.com
```

使用 TCP 443 可以减少 ICMP 被限速造成的误判。记录晚高峰与凌晨各一次结果，比较跨境出口、海外 Transit 和最终落地是否变化。若某跳延迟突然增加，但后续跳又恢复，通常是该路由器低优先级回复探测包；若从某跳开始后续所有节点都保持高延迟，才更可能存在真实排队。

Windows 用户也可先运行：

```powershell
tracert -d target.example.com
Test-NetConnection target.example.com -Port 443 -InformationLevel Detailed
```

`-d` 禁止反向 DNS，避免查询时间干扰。记录源地址、目标地址与时间，便于复盘 BGP 变化。

## 用 MTR 看持续抖动

单次 traceroute 只是快照，MTR 才能揭示时间维度。推荐至少发送 100 个探测包，并输出报告模式：

```bash
mtr -rwzc 100 target.example.com
mtr --tcp --port 443 -rwzc 100 target.example.com
```

| 字段 | 含义 | 判断重点 |
| --- | --- | --- |
| Loss% | 探测包丢失比例 | 是否从该跳持续传递到终点 |
| Avg | 平均 RTT | 适合比较整体路径 |
| Worst | 最大 RTT | 发现偶发排队尖峰 |
| StDev | RTT 标准差 | 衡量抖动与稳定性 |
| Last | 最后一次 RTT | 不能单独作为结论 |

若中间某跳 Loss 80%，后续和终点却是 0%，说明该设备只是不愿回复探测包，不代表转发丢包。若某跳开始出现 5%，之后所有跳包括终点都接近 5%，才值得关注。家庭路由器第一跳就抖动，通常是 Wi-Fi、网线、光猫负载或本地上传占满，不应归因于跨境链路。

## 三网典型拥堵特征

电信 163 公网出口在部分方向晚高峰会出现明显排队，表现为跨境前后 RTT 突增并伴随重传；CN2 路径通常更稳定，但不同城市接入质量仍有差异。联通 4837 的优势方向与互联策略随地区变化，9929 往往更受控。移动 CMI 在亚洲方向常有较短路径，但本地省网互联和海外回程仍会影响实际表现。

这些标签不是质量保证。真正的测试要固定用户城市、运营商、目标和时间。大佬云所谓三网入口优化，应该通过同一落地节点下三种宽带的端到端结果验证，而不是只看路由名称。

## IEPL 为什么跳数更少

二层或受控承载在入口与落地之间不按普通公网 IP 路由逐跳暴露，因此 traceroute 可能从国内入口直接跳到海外落地。它减少的是公共国际出口的不确定性，并不意味着物理距离消失。端到端 RTT 仍受光纤距离、接入路由和落地网络影响。验证 IEPL 应关注晚高峰与非高峰的差值：若延迟、丢包和单线程吞吐全天接近，说明承载隔离较有效。

| 观察项 | 公网拥堵路径 | 受控专线路径 |
| --- | --- | --- |
| 晚高峰 RTT | 明显抬升 | 变化较小 |
| 路由可见性 | 多个公网 ASN | 中间承载不可见 |
| 丢包位置 | 国际出口后持续 | 入口或落地更易定位 |
| 故障恢复 | 依赖 BGP 收敛 | 可切换备用入口 |

## 从结果到工单

提交问题时附上四组证据：本地运营商与城市、异常时间、TCP MTR、真实业务 TTFB。敏感信息如订阅地址必须打码。不要只发一张客户端节点全红截图，因为它缺少目标、协议和路径信息。

```bash
date
curl -s https://ipinfo.io/json
mtr --tcp --port 443 -rwzc 100 target.example.com
curl -o /dev/null -sS -w '%{time_connect} %{time_starttransfer} %{speed_download}\n' https://target.example.com/test.bin
```

如果需要调整客户端的路由模式、DNS 或 TUN 设置，请先阅读[客户端配置](../../../tutorials.html)。每次只改变一个变量并保留前后结果。NextTrace 告诉你“路径经过哪里”，MTR 告诉你“问题是否持续”，真实业务测试则回答“用户是否受影响”；三者合在一起，才能形成可靠结论。
